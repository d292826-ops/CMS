# ЦМС — учёт выдачи ресурсов

Внутреннее приложение по ТЗ от 9 сентября 2026: выдача запчастей, материалов, топлива и газа, возвраты, бюджеты подразделений и отчёты. Интерфейс на русском, валюта — рубли, начальный часовой пояс — Asia/Kamchatka.

## Возможности

- Справочники получателей, автомобилей, зданий, подразделений, ресурсов; поиск, редактирование, архив.
- Многострочные документы, черновики, проведение, возвраты к исходным строкам, отмена с причиной и журнал действий.
- Дашборд, рейтинги, динамика, карточки объектов, отдельная аналитика топлива по видам и единицам.
- Месячные бюджеты по трём статьям; копирование месяца, повторение на год и распределение годовой суммы с сохранением копеек.
- Подробный отчёт и настоящий `.xlsx` со всеми строками выбранного фильтра и числовыми ячейками.
- Серверные права администратора, оператора и финансиста. Демо и рабочие записи разделены полем workspace во всех запросах.
- D1 хранит данные. localStorage для учёта не используется. R2 сохраняет запрошенные резервные копии.

## Стек и запуск

Node.js 22.13+ (для встроенных SQLite-тестов рекомендуется Node 22.16+), React 19, Vinext / Vite, TypeScript, Cloudflare Workers, D1 SQLite, Drizzle migrations, R2, Shadcn UI и Recharts. Точные версии в `package-lock.json`.

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_flashy_steel_serpent.sql
npm run dev
```

В чистом клоне используется portable-профиль. Локальные миграции применяются один раз и по порядку. Локальная имитация входа работает только на loopback в portable-профиле: `/signin-with-chatgpt?return_to=/`. Она не включается в production. Локальный пользователь `seedy@sites.test` не переносится в размещённую базу.

При работе в ChatGPT Sites используются штатные процедуры установки, сборки, сохранения и публикации. `.openai/hosting.json` содержит идентификатор этого сайта и логические привязки `DB`, `BUCKET`. Этот файл не является конфигурацией произвольного Cloudflare-аккаунта. Размещение вне Sites требует отдельной настройки аутентификации и доверенного шлюза; нельзя просто принимать пользовательские `oai-authenticated-user-*` заголовки из интернета.

GitHub хранит исходники. GitHub Pages не исполняет серверные обработчики, не предоставляет D1 и не заменяет хостинг этого приложения.

## Первый вход и рабочая база

Сайт первоначально закрыт для владельца. Первый вошедший владелец создаёт запись администратора; до его первого входа нельзя расширять аудиторию сайта. В меню выбран демонстрационный режим. Переключатель «Рабочая база» открывает пустые рабочие справочники.

В рабочем режиме администратор добавляет пользователей по email их ChatGPT-аккаунтов и назначает роли. Чтобы сотрудники могли открыть сайт, им также нужен доступ на уровне публикации Sites. Успешный вход сам по себе не даёт права: все API проверяют серверный список пользователей.

Демонстрационные роли выбираются только администратором и только для demo. Они не создают общедоступные пароли и не меняют рабочие роли.

## Структура

- `app/api/` — защищённые API выдачи, отчётов, настроек и копий.
- `components/cms/` — рабочий интерфейс.
- `lib/domain.ts` — арифметика, даты и бюджетные статусы.
- `lib/mutations.ts` — правила проведения и изменения данных.
- `lib/queries.ts` — общие фильтры и аналитика.
- `lib/server.ts` — проверка прав, идемпотентность, аудит, транзакции.
- `db/schema.ts`, `drizzle/` — схема и миграции.
- `lib/seed.ts` — связанные контрольные примеры текущего и прошлого месяца.
- `tests/run.mjs` — проверки бизнес-логики на SQLite с тестовым адаптером D1.
- `docs/USER_GUIDE.md`, `docs/OPERATIONS.md`, `docs/ACCEPTANCE.md` — инструкции и результаты.

## Правила расчётов

Цена хранится в целых копейках, количество — в тысячных единицы. Умножение выполняется через BigInt с HALF_UP, итог — сумма округлённых строк. При возврате используется накопленная округлённая стоимость, ограниченная оставшейся суммой исходной строки; последний полный возврат забирает копеечный остаток. Это также корректно после отмены ранее проведённых частичных возвратов.

Проведение и отмена выполняются атомарным D1 batch. Проверка ревизии workspace в CHECK-ограничении предотвращает параллельный перерасход возврата и потерю конкурентных изменений. Клиентский ключ повторного запроса сохраняется вместе с документом. Чтение аналитики повторяется при изменении ревизии, чтобы показатели внутри ответа не расходились.

Отмена исключает документ из исходного периода, возврат уменьшает период своей операции. Черновики не влияют на учёт. Цена, название, код, группа, единица и имена получателя/объекта сохраняются в документе.

## Перед регулярной эксплуатацией

Ежедневный автоматический запуск резервного копирования не настроен в текущем размещении. Код отдельного Worker `ops/backup-worker.ts` подготовлен; инструкция подключения и хранения 31 день — в `docs/OPERATIONS.md`. Ручная копия уже доступна администратору. Проверка восстановления выполнена в отдельной SQLite-базе.

Нагрузочное испытание на согласованном production-сервере (20 пользователей / 100 000 строк / 3 секунды) и браузерная приёмка не выполнялись. Полное соответствие этим эксплуатационным пунктам не заявляется.

## Публичная демонстрация

Корневая ссылка открывает демоверсию без аккаунта ChatGPT. Гости могут просматривать примеры, фильтровать отчёты и скачивать Excel. Публичные примеры хранятся отдельно от рабочей базы и редактируемой демонстрационной базы сотрудников; запись, настройки, пользователи, аудит и резервные копии гостям недоступны.

Для рабочей базы используется вход через ChatGPT и активная роль пользователя. Первого администратора можно создать только при совпадении почты с серверной настройкой `CMS_OWNER_EMAIL`; без этой настройки автоматическое назначение администратора отключено. Значение задаётся в окружении размещения, а не в исходниках.
