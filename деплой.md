## Как зайти на сервер

Это управляемый хостинг Sites, согласованный вместо VPS. SSH-доступ к виртуальной
машине здесь не предоставляется; команда `ssh root@...` не является способом управления этим сайтом.
Администрирование выполняется через подключённый Sites в аккаунте владельца.

Проверенный порядок доступа для ИИ-оператора:

1. Прочитать `.openai/hosting.json`, взять существующий `project_id`:
   `appgprj_6aa0d225ade081919343ff3b5fcae4af`.
2. Вызвать `get_site`: проверить роль `owner`, статус `active`, адрес и доступ `public`.
3. Для исходников вызвать `create_source_repository_write_credential`.
   Передать временный доступ только через скрытый stdin штатного `site-workflow.mjs`;
   использовать возвращённый checkout. Не записывать токен в файл, чат, git или команды.
4. Для диагностики использовать `get_site_worker_logs`; для версии —
   `list_site_versions` и `get_site_version`; для размещения —
   `save_site_version`, затем `deploy_site_version`.
5. При незавершённом размещении опрашивать `get_deployment_status` до итогового статуса.
   Для отката передавать точный идентификатор ранее сохранённой версии.

Так выполняются действия, для которых в варианте с VPS использовался бы SSH:
получение кода, сборка, публикация, просмотр ошибок и возврат к прежнему релизу.

### Как скачать и проверить копию

1. Открыть начало демонстрации и раздел «Резервные копии».
2. Нажать «Скачать резервную копию JSON», дождаться файла в загрузках и сохранить его отдельно.
3. Файл формата `otdel-snabzheniya-backup-v1` содержит состояние версии 1 целиком:
   заявки, документы, подтверждения, движения запаса, операции, справочники и выбранного участника.
4. Копия допускается до 2 МБ. Имена и финансовые сведения в этом проекте вымышленные.
   Пользовательские файлы копий не включать в публичный git.

### Как восстановить фактические изменения

1. Открыть начальный экран, выбрать JSON в поле «Загрузить резервную копию JSON».
2. Сайт проверит формат, версию, поля, связи, количества и согласованность операций.
   Выбор файла сам по себе не меняет состояние.
3. Проверить дату, число заявок и документов, нажать «Восстановить копию».
   Сохранённое корректное текущее состояние предварительно попадёт в автокопии;
   несохранённый ввод будет отменён.
4. Заявки, выданные детали и подтверждения возвращаются из снимка;
   выдачи и расходы не проводятся второй раз. Ревизия повышается для защиты от устаревших форм.
5. Если после предпросмотра состояние изменилось в другой вкладке, замена блокируется:
   повторно выбрать копию и проверить подтверждение.
6. Для отката внутри того же браузера выбрать снимок в «Автокопия перед изменением» →
   «Восстановить выбранную автокопию» → подтвердить.
7. Если история повреждена, сначала скачать корректный текущий набор. Затем
   «Начать новую историю копий» с отдельным подтверждением: первичный набор не сбрасывается.

### Политика и проверенное восстановление

- Отдельный cron не нужен: в закрытом браузере демонстрационные операции не выполняются;
  резервирование привязано к каждому сохранению, а не к времени суток.
- При недоступности/переполнении хранилища автокопия не создаётся и изменение отменяется.
  Сайт сообщает об ошибке; прежний первичный набор остаётся.
- История в том же браузере защищает от ошибочного действия, но исчезает при очистке
  всего хранилища. Для такого случая реализован отдельный скачиваемый JSON.
- Проверено восстановление реального учебного изменения после полного
  `localStorage.clear()`: вернулись созданная заявка, выдача, обе стороны подтверждения
  и расход 1 000 ₽; второе движение запаса не появилось.
- Проверены отмена восстановления, неверный/чужой JSON, нарушенные связи,
  файл больше лимита, конфликт другой вкладки, отказ записи и повреждённый основной набор.
- Протокол: `app/tests/results/backups.json`; дополнительные тесты: `app/tests/backups.test.ts`.
- Команды очистки старой D1/R2 прежнего CMS не запускались. Новое демо к ним не привязано;
  восстановление той отдельной системы требует отдельной проверки её ресурсов.

2. Если новая публикация неуспешна, проверить её сообщение об ошибке и журналы;

   Для следующих обновлений новой демонстрации использовать сохранённую версию №3
   как первую точку возврата именно к «Отделу снабжения».
4. Локально дважды нажать `app/Запустить сайт.command`; окно терминала оставить открытым.
5. После исправления повторить сборку и основной сценарий, записать результат и версию.
