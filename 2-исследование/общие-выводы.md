## Что расходится

**Объём первой версии.** R1 предлагает сценарий четырёх ролей с финансовым результатом. R2 предлагает начать с одной операционной роли и отложить финансовую часть, хотя в другом разделе допускает четыре роли.

Для нашего диплома сохраняем согласованную главную задачу — понимать результат каждой машины. Сокращаем количество примеров и операций, сохраняя короткий сценарий всех участников.

**Состав альтернатив.** R1 больше рассматривает складские инструменты и системы учёта, R2 — управление автопарком и обслуживанием. Разные списки расширяют выбор. Отсутствие продукта в одном отчёте не является отрицательной оценкой.

**Достоверность отдельных утверждений.** При проверке обнаружены ошибки R2:

- **MaintainX:** REST API доступен в Premium, а ERP/business integrations перечислены в Enterprise. Утверждение «API только Enterprise» смешивает разные возможности. [Официальные тарифы](https://www.getmaintainx.com/pricing).
- **Fleetbase:** разработчик разрешает самостоятельное размещение для собственных коммерческих операций по AGPL. Коммерческая лицензия не обязательна для любого промышленного использования. [README разработчика](https://github.com/fleetbase/fleetbase#license).
- **Завгар Онлайн:** единица «за 1 ТС в месяц» подтверждается. Утверждение о снижении цены с 2000 до примерно 1000 рублей именно при годовой оплате не подтверждено для одного тарифа. Расчёт стоимости на 600 машин из R2 не принимаем без уточнения предложения. [Официальные тарифы](https://zavgar.online/tarify).

Также R2 делает категорические выводы о доступности зарубежных поставщиков и соответствии российских вариантов требованиям к данным. Собранных сведений недостаточно, чтобы считать эти выводы установленными.

## Общие паттерны рынка

Наблюдения относятся к рассмотренной выборке.

1. **Функции группируются вокруг разных задач.** Складские системы организуют движение деталей, системы обслуживания — ремонты, финансовый учёт — доходы и расходы. Для их связи нужны общие идентификаторы машин и документов.
2. **Затраты раскрываются подробнее, чем заработок машины.** Доходная часть остаётся обязательным элементом нашего проекта.
3. **Нужные возможности зависят от тарифа.** Наличие склада, закупок или API у продукта не означает их доступности в начальном плане.
4. **Стартовая цена не является сметой для 600 машин.** Например, Fleetio прямо связывает опубликованные ставки с диапазоном пяти единиц техники. [Условия тарификации](https://www.fleetio.com/pricing).
5. **Открытый код требует сопровождения.** При выборе важны зрелость проекта, документация, обновления и возможность поддерживать его.
6. **Финансовая информация начинается с операционных действий.** Удобство регистрации заявки, выдачи и возврата влияет на полноту последующей аналитики.
7. **Чужой экономический эффект нельзя переносить на компанию.** Наши исходные потери и методика их измерения пока не установлены.

## Выводы для нашего проекта

**Сохраняем выбранный вариант: «АвтоКонтроль» — учебное веб-приложение с кодом в GitHub и демонстрационными данными.**

Первая версия показывает четыре роли:

- **Механик:** создаёт заявку на запчасть для машины.
- **Кладовщик:** находит деталь и оформляет выдачу.
- **Финансовый директор:** анализирует расходы и причины отклонений.
- **Собственник:** видит доходы, учтённые расходы и результат каждой машины.

Главная ценность — **понимать, сколько машина заработала и из чего сложился результат**.

В демонстрации раскрываем формулу «доходы минус включённые расходы» и состав этих расходов. При неполном составе затрат называем показатель результатом по учтённым статьям.

Для реальной эксплуатации оба отчёта дают основание начать с обследования существующей 1С. Источник доходов, полный состав затрат и величина потерь пока не установлены; численное обещание экономии или окупаемости исследованием не обосновано.
